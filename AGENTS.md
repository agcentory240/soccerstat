# AGENTS.md — инструкции для ИИ-агентов

## 0. Язык работы — русский

**Обязательное правило:** все рассуждения (thinking / chain-of-thought), планы, ответы пользователю, комментарии в коде, коммиты и документация выполняются **на русском языке**.

- Код, имена переменных, функций, классов, полей API и названия технологий остаются на английском согласно общепринятым конвенциям.
- Технические термины не переводятся, если перевод ломает однозначность (`upsert`, `middleware`, `migration`, `workspace`).
- Если пользователь явно попросил другой язык ответа — следуй его указанию, но внутренние рассуждения всё равно веди на русском.

Это правило приоритетнее любых дефолтных настроек модели и инструментов.

## 1. Что это за проект

**SoccerStat** — клиент-серверное приложение для парсинга списка футбольных матчей с `nb-bet.com`, сохранения их в PostgreSQL и последующего AI-анализа:

1. Парсер собирает матчи и коэффициенты (Playwright + JSDOM).
2. Быстрая AI-модель оценивает матчи по шкале 0–10 и выделяет перспективные.
3. Deep-модель делает подробный разбор выбранного матча и сохраняет решение (`СТАВИТЬ` / `НАБЛЮДАТЬ` / `ПРОПУСТИТЬ`).
4. React-фронтенд показывает список, детали и результаты анализа.

Проект — **единый npm-workspaces монорепозиторий**:

| Путь | Пакет | Назначение |
|---|---|---|
| `app/` | `@soccerstat/api` | NestJS 12, TypeORM, PostgreSQL, RabbitMQ, Playwright |
| `frontend/` | `@soccerstat/frontend` | React 19, Vite 8, Zustand, React Router, Tailwind 4 |
| `docker-compose.yml` | — | PostgreSQL, pgAdmin, RabbitMQ, API |
| `docs/ai/` | — | Подробные инструкции для агентов |

Исходные отдельные git-репозитории `app` и `frontend` удалены. Актуальный репозиторий — корневой `soccerstat`.

## 3. Быстрый старт

```bash
# из корня репозитория
cp .env.example .env        # заполнить AI_API_KEY
npm install                 # установка зависимостей всего workspace
npm run dev                 # API + фронтенд одновременно

# либо инфраструктура в Docker
npm run docker:up           # требует AI_API_KEY в .env
```

- API: `http://localhost:3000`
- Frontend: `http://localhost:5173`
- pgAdmin: `http://localhost:5050`
- RabbitMQ UI: `http://localhost:15672`

Рекомендуемая версия Node.js — **22 LTS**. На Node 20 основная сборка работает, но часть инструментов NestJS CLI 12 выдаёт предупреждения `EBADENGINE`.

## 4. Основные команды

Все команды выполняются **из корня** репозитория.

| Команда | Действие |
|---|---|
| `npm run dev` | Запуск API (`watch`) и Vite одновременно |
| `npm run dev:api` | Только API |
| `npm run dev:web` | Только фронтенд |
| `npm run build` | Сборка API и фронтенда |
| `npm run build:api` | Сборка NestJS |
| `npm run build:web` | `tsc -b && vite build` |
| `npm run lint` | oxlint (API) + ESLint (frontend) |
| `npm test` | Unit-тесты API (Vitest) |
| `npm run test:e2e` | E2E-тесты API |
| `npm run migrate:show` / `migrate:run` / `migrate:create` | TypeORM-миграции |
| `npm run docker:up` / `docker:down` / `docker:logs` | Docker Compose |

Не запускай `npm install` внутри `app/` или `frontend/`: зависимости и lock-файл находятся в корне workspace.

## 5. Правила работы агента

### 5.1. Перед изменениями

1. Прочитай `AGENTS.md` и профильный документ из `docs/ai/`.
2. Найди существующую реализацию и переиспользуй её. Не создавай дублирующие сервисы, хелперы и типы.
3. Определи, к какому workspace относится задача (`app` или `frontend`).
4. Если меняется контракт API — синхронизируй backend и `frontend/src/types/match.ts`.

### 5.2. При изменениях

- Делай минимальные точечные изменения, не рефактори несвязанный код.
- Соблюдай стиль проекта: backend — ESM-импорты с расширением `.js`, frontend — функциональные компоненты и хуки.
- Комментарии и тексты ошибок — на русском, если это пользовательские сообщения.
- Не добавляй новые зависимости без необходимости. Если добавил — обнови корневой `package-lock.json`.
- Не меняй AI-промпты без прочтения [`docs/ai/ai-pipeline.md`](docs/ai/ai-pipeline.md).

### 5.3. Запрещено

- Коммитить `.env`, API-ключи, токены и пароли.
- Коммитить `node_modules/`, `dist/`, `app/debug/`, `coverage/`, `*.tsbuildinfo`.
- Удалять или переписывать миграции, которые уже применялись.
- Менять `docker-compose.yml` так, чтобы секреты снова оказались в репозитории.
- Запускать destructive-команды (`rm -rf`, `git reset --hard`, `git clean -fdx`) без явного разрешения пользователя.
- Работать внутри `app/.git` или `frontend/.git` — этих репозиториев больше нет.

### 5.4. После изменений

Обязательный минимум проверки:

```bash
npm run lint
npm run build
```

Если затронуты сервисы/парсер/анализ:

```bash
npm test
```

В финальном ответе укажи:

- что изменено и в каких файлах;
- какие проверки выполнены и их результат;
- что осталось сделать или какие есть риски.

## 6. Архитектурные инварианты

- HTTP API и RabbitMQ-микросервис запускаются из одного NestJS-процесса (`app/src/main.ts`).
- Очередь RabbitMQ: `matches_queue`; события: `matches.parsed`, `matches.analyzed`.
- Основная сущность — `MatchEntity` (`app/src/matches/match.entity.ts`), таблица `matches`.
- Парсер пишет отладочный HTML в `app/debug/` (каталог исключён из git).
- Оценка матча хранится в `aiScore` (0–10), глубокий анализ — в `deepAnalysis` (JSONB) и связанных полях.
- Фронтенд получает данные только через HTTP API, без прямого доступа к БД.
- CORS включён в `main.ts`; фронтенд обращается к API по адресу `http://localhost:3000`.

## 7. Definition of Done

Задача считается выполненной, когда:

- изменения соответствуют описанной архитектуре;
- `npm run lint` и `npm run build` проходят;
- контракты API и типы фронтенда согласованы;
- секреты и артефакты сборки не попали в git;
- документация в `docs/ai/` обновлена, если изменились архитектура, команды или контракты.
